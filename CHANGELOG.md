## [0.14.0] — 2026-07-13

### Security
- H1: эфемерные TURN-креды. Вместо вечного общего логина/пароля /config
  выдаёт на каждый запрос свежие HMAC-SHA1 креды (TURN REST API,
  static-auth-secret); секрет только на сервере. Закрывает использование
  нашего TURN как открытого релея.
- H3: привязка личности в чате. Входящий конверт нормализуется по
  транспортному отправителю (envelope.from := fromPeerId) — участник больше
  не может слать/редактировать/удалять сообщения от чужого имени.
- M2: строгие security-заголовки на фронте (Cloudflare Pages _headers):
  CSP (script/style 'self', frame-ancestors 'none'), X-Frame-Options: DENY,
  Permissions-Policy на camera/microphone/display-capture=self.

### Added
- UI лимита созвона: таймер оставшегося времени у счётчика участников
  (жёлтый ≤10 мин, красный ≤60 с), оверлей «Время созвона истекло» с
  корректным teardown при room-expired.

## [0.13.0] — 2026-07-13

### Added
- Жёсткий лимит длительности созвона: комната живёт максимум
  MAX_ROOM_LIFETIME_SECONDS (по умолчанию 3 часа) с момента создания —
  по истечении сервер шлёт всем room-expired и удаляет комнату; joined
  несёт expiresInSeconds для обратного отсчёта на клиенте.

### Security
- Защита от DoS: cap размера релея (16КБ) и WS-кадра (64КБ), общий
  rate-limit на все релеи (100/10с), потолок числа комнат (MAX_ROOMS=500)
  и per-IP лимит создания комнат/заявок в лобби (10/60с по CF-Connecting-IP).
- Security-заголовки на API-ответах: X-Content-Type-Options: nosniff,
  Referrer-Policy: no-referrer.

## [0.10.0] — 2026-07-13

### Added
- Ключ `#k` сознательно остаётся в адресной строке: перезагрузка страницы не
  выбрасывает из комнаты, копирование URL из строки даёт рабочую ссылку
  (одноразовый `#lt` лидера по-прежнему вычищается немедленно).
- Ш1: E2E-шифрование сигналинга. Ключ комнаты `k` (32 случайных байта)
  генерируется клиентом при создании комнаты и живёт только во фрагменте
  ссылки — сервер его не видит. Из `k` через HKDF-SHA256 выводятся три
  AES-256-GCM ключа (`static/crypto.js`): sdp/candidate/`stream-info` в
  серверном релее, отображаемое имя участника в `join-room`, и адресный
  fallback-конверт чата — теперь для сервера это непрозрачные блобы, а не
  открытый текст (P2P-шина и медиатреки не тронуты — WebRTC и так гонит их
  поверх DTLS).

### Changed
- QR-код в попапе «Поделиться» рендерится ЛОКАЛЬНО в браузере (вендоренный
  `qrcode-generator`, см. `static/vendor/qrcode.js`) вместо серверного
  `GET /qr.svg` (эндпоинт удалён вместе с крейтом `qrcode`) — ссылка с
  секретным `#k` больше не уходит на сервер ради картинки.
- Валидация имени участника на сервере ослаблена (лимит 32 -> 512 символов):
  поле теперь несёт шифрблоб, а не открытое имя, и сервер не может (и не
  должен) проверять его содержимое.

## [0.8.0] — 2026-07-12

### Added
- Система прав: лидер комнаты (создатель через одноразовый leaderToken в
  URL-фрагменте; при уходе — сервер назначает старейшего по подключению),

## [0.7.0] — 2026-07-12

## [0.5.0] — 2026-07-12

### Added
- Передача файлов, картинок и аудио в чате — строго peer-to-peer: оффер в
  ленте (виден и опоздавшим из истории), передача лениво по запросу отдельным
  DataChannel чанками по 16КБ с backpressure, лимит 25МБ. Картинки ≤2МБ —
  автоскачивание с инлайн-превью, аудио — плеер, прочее — карточка с кнопкой.
  Скрепка, drag&drop, вставка картинки из буфера. Файловые байты через сервер
  не ходят никогда: парам без прямого P2P-соединения передача честно
  недоступна.

### Fixed
- Потеря хвоста файла: RTCDataChannel.close() сразу после очереди send()
  молча ронял недосланные байты — теперь отправитель дожидается
  bufferedAmount=0 перед закрытием канала.

## [0.4.0] — 2026-07-12

### Changed
- **Чат стал peer-to-peer**: сообщения идут напрямую между участниками по
  RTCDataChannel поверх mesh — сервер их не видит и не хранит вовсе. История
  для входящих — от старейшего пира; единый порядок — лампорт-часы; сервер
  оставлен только адресным fallback-транзитом (шифротекст конверта, ≤8КБ,
  без хранения) для пар, у которых P2P не пробился.
- Конверт сообщения расширяемый ({v,id,lamport,from,kind,...}) — под будущие
  реакции, реплаи и передачу файлов.

### Fixed
- Обойдён баг Chrome: при быстром создании нескольких RTCPeerConnection с
  симметричными negotiated-DataChannel у части пар никогда не срабатывал
  onnegotiationneeded — шина переведена на классический асимметричный
  паттерн (createDataChannel у impolite-стороны).

## [0.3.0] — 2026-07-12

### Changed
- **Полная эфемерность: SQLite удалён.** История чата живёт в памяти комнаты
  (последние `CHAT_HISTORY_CAP`, по умолчанию 50) и умирает вместе с ней —
  после завершения сессии не остаётся никаких данных: ни чатов, ни сессий;
  IP и порты клиентов не логируются и не хранятся. Из деплоя удалён PVC.
- Короткие ссылки комнат: `/r/<id>` вместо `/room/<id>`.
- Мобильная вёрстка комнаты: нижняя панель с крупными touch-таргетами и
  safe-area, сетка тайлов 2 колонки, лента тайлов при активном экране,
  фронтальная камера по умолчанию, кнопка «Экран» скрывается на устройствах
  без поддержки захвата (мобильные браузеры не дают getDisplayMedia).

### Added
- Попап «Поделиться»: QR-код комнаты (серверный SVG `GET /qr.svg?room=<id>`,
  чистый Rust-крейт qrcode) + ссылка с копированием.

## [0.2.0] — 2026-07-12

### Changed
- **Модель комнаты: симметричная встреча вместо «вещающий + зрители»** (протокол
  v2, breaking). Все участники равны и соединены full mesh (WebRTC каждый с
  каждым, до 6 человек); роли broadcaster/viewer удалены, страницы объединены
  в одну комнату с сеткой тайлов.
- Комната создаётся мгновенно кнопкой на главной (`POST /api/rooms`) с
  переходом по ссылке — без диалога захвата экрана; пустая комната живёт
  `EMPTY_ROOM_TTL_SECONDS` (по умолчанию 120с).
- Прекращение показа экрана больше не завершает сессию: комната живёт, пока
  в ней есть хотя бы один участник.

### Added
- Видео и голос у каждого участника: независимые кнопки микрофона и камеры
  с мгновенным mute/unmute (`track.enabled`, без ренегациации); заглушки
  тайлов при выключенной камере, speaking-рамки.
- Показ экрана любым участником, не более одного за раз: серверный «замок»
  (`share-start`/`share-started`/`share-rejected`/`share-stopped`), автосброс
  при дисконнекте владельца.
- Сериализованный писатель истории чата — устранена гонка, при которой
  входящий мог не увидеть только что отправленное сообщение в истории.

## [0.1.0] — 2026-07-12

### Added
- Шеринг экрана «один вещает — до 5 зрителей»: mesh P2P WebRTC звездой вокруг
  вещающего, сигналинг-релей на Rust/axum поверх WebSocket, медиа через сервер
  не проходит. Ванильный фронтенд без сборщиков, тёмная тема.
- Текстовый чат комнаты с историей в SQLite (последние 50 сообщений новому
  зрителю), именами участников и rate-limit'ом.
- Микрофон зрителя (perfect negotiation, ренегациация) и аудио-хаб: вещающий
  ретранслирует микрофоны зрителей остальным; честная индикация «кто говорит»
  (RMS-анализ, устойчивый к жизненному циклу AudioContext).
- Серверный ping/pong-хартбит против тихих обрывов сети.
- Два уровня тестов: протокол сигналинга (43 проверки, чистый Node) и
  браузерные e2e (Playwright + системный Chrome, basic 13 + resilience 16),
  включая режим полностью реальных медиа (E2E_TRY_REAL_CAPTURE/MIC).
- Деплой в KubeSolo (chat.fedorov.it через Cloudflare Tunnel): автодеплой из
  GitHub Actions по пушу в main, гейт тестами, иммутабельные теги prod-<sha>,
  /healthz и /version.json.
